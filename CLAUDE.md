# CLAUDE.md

Top-down 2D shooter written in C++17 with Qt5 Widgets + `QGraphicsScene`. One human `Player` vs one AI `Bot`, chests with loot, three guns, grenades, leaderboard.
One class per lowercase `.h/.cpp` pair, kept side by side in folders by game area. Some comments and the TODO list at the bottom of `main.cpp` are in Polish.

## Layout

- `main.cpp`, `README.md` (screenshot in `docs/`), `shooter.pro` (the game), `game.pri` (every game source except `main.cpp`; shared by the game and the tests): project root
- `tests/`: Qt Test suite (`tests.pro`, one `test_*.cpp` per area, shared setup in `helpers.h`)
- `core/`: `global_consts.h`, `GameClock` / `GameTimer` (game time that pauses), `Settings` (options kept between runs)
- `ui/`: windows, menus, HUD and overlays (`MainWindow`, `MainMenu`, `MainWidget`, `OptionsWidget`, `PlayerBarWidget`, `Leaderboard`, `LeaderboardSlot`, `Countdown`, `MessageAtTopOfScreen`, `PowerGrenadeThrowing`, `PauseMenu`, `RoundOverWidget`)
- `world/`: map, view and scene items (`Map`, `MapWidget`, `MapView`, `FieldOfView`, `ShotMarker`, `GridElement`, `ItemsOnScene`, `Building`, `Chest`, `ShakeScreen`)
- `characters/`: heroes and AI (`Hero`, `Player`, `Bot`, `HeroStats`, `BFS_Algorithm`)
- `weapons/`: guns and projectiles (`Gun`, `Pistol`, `Rifle`, `Shotgun`, `Sniper`, `Shooting`, `Bullet`, `Grenade`, `GrenadeEllipseItem`)

Project includes are written relative to the root (`#include "characters/hero.h"`). `INCLUDEPATH += $$PWD` in `game.pri` makes that work. Don't use bare names or `../` paths.

## Build / run

qmake project: `shooter.pro`. Build out of source:

```bash
mkdir -p build && cd build && qmake ../shooter.pro && make -j && ./shooter
```

- Builds with both Qt 5.15 (system `qmake`) and Qt 6.11 (`~/Qt/6.11.2/gcc_64/bin/qmake`, the kit Qt Creator uses). Include Qt headers explicitly: Qt 5 is stricter about transitive includes (e.g. `qApp` needs `<QApplication>`).
- There is no Designer form. `MainWindow` is built in code, so keep `FORMS +=` empty unless a `.ui` file is actually committed.
- New class → put both files in the matching folder and add them as `$$PWD/<folder>/<file>` to `SOURCES` / `HEADERS` in `game.pri`, not `shooter.pro`.
- No CI yet.

## Tests

```bash
mkdir -p build/tests && cd build/tests && qmake ../../tests/tests.pro && make -j && make check
```

- Qt Test, one executable (`tests`), running offscreen unless `QT_QPA_PLATFORM` is set. It takes ~60 s, mostly real-time tests: the 8 s smoke test, the menu/pause/round flow (`TestFlow`, ~28 s), the shot marker timings and real grenade throws. `tests/main.cpp` points `QSettings` at a temporary folder, so tests never touch the player's options. Run it after every change, with both Qt versions for anything build-related.
- For memory errors and leaks, build it with `CONFIG+=debug "QMAKE_CXXFLAGS+=-fsanitize=address -fno-omit-frame-pointer" "QMAKE_LFLAGS+=-fsanitize=address"` and run with `LSAN_OPTIONS=suppressions=../../tests/lsan.supp ./tests` (from `build/<dir>`). The game frees everything at exit; the suppression file only hides a few bytes inside Qt's offscreen plugin. A leak makes the run fail.
- `./tests` takes no filter: an argument is read as a test function name by every test class, so nothing runs.
- `World` in `helpers.h` builds a map, the player and the overlays the way the game does. `MapWidget`'s destructor cleans up whatever bots, bullets and grenades a test leaves on the scene.
- Tests that need internals are friends of the class (`Bot` → `TestBot`, `Bullet` → `TestWeapons`, `Grenade` → `TestBot` and `TestWeapons`, `MapWidget` → `TestFlow`). Add a `friend class` line rather than `#define private public`.
- New test class: add a `test_*.cpp` ending with `#include "test_*.moc"` and a `runTest*()` function, list it in `tests.pro`, and call it from `tests/main.cpp`.
- `compile_commands.json`, `*.pro.user` and `.qtcreator/` are local IDE state. They're gitignored and untracked, so don't commit them. The local `compile_commands.json` is stale (it points at `/home/szymon/c++ projects/shooter`).
- Build into `build/` (gitignored), never in-source.

## Architecture

- **Widgets:** `MainWindow` (`QStackedWidget`, fixed 1024×720) → `MainMenu` / `MainWidget` / `OptionsWidget`. `MainMenu` and `OptionsWidget` emit signals for their buttons (`startClicked`, `backClicked`, …), which `MainWindow` connects.
- **Game lifetime:** every new game is a new `MainWidget` (`MainWindow::startProgram`); `endGame()` deletes it and everything in it. Back to menu from the pause menu (`leaveGame`) keeps the game frozen behind the menu: the menu then shows Continue (`continueGame`, which resumes it) and "Start game" reads "New game" (which ends the frozen one first). Back to menu from the round-over screen ends the game. While a game exists, Options locks the round length. Signals from inside the game to `MainWindow` are queued, since they may delete the widget that sent them.
- **Pause:** Esc in `MapWidget` emits `pauseRequested`; `MainWidget::pause` lets go of the controls (`MapWidget::releaseControls`), pauses the `GameClock` and shows `PauseMenu` (Resume, Back to menu; Esc there resumes). While the clock is paused `MapWidget` ignores keys and `MapView` the mouse.
- **Round:** its length (1, 3 or 5 min, `Settings::roundMinutes`, default 3, chosen in Options, stored with `QSettings` as an ini file) is set by `MainWindow` before `MapWidget::start`. The round starts when the 3 s countdown ends (`roundTimer`; when it fires, `roundTimeUp` ends the round only if the game clock agrees, since timers may fire a few ms early); the bar shows the time left (`PlayerBarWidget::updateTimeLeft`, refreshed by `roundClock`). When it runs out `MapWidget::endRound` lets go of the controls, pauses the clock and emits `roundOver`; `MainWidget` shows `RoundOverWidget`: the winner by kills (`resultFor`: most kills wins, equal top kills is a draw), the table, Play again / Back to menu. No pausing over it.
- **`MainWidget`** owns `MapWidget` + `PlayerBarWidget` (HUD) and overlay widgets placed with absolute `move()`: `Countdown`, `MessageAtTopOfScreen`, `PowerGrenadeThrowing`, `Leaderboard`. It injects the overlays into `MapWidget` via setters.
- **`MapWidget`** is the game hub. It owns the `QGraphicsScene`, `MapView` (a `QGraphicsView` that emits mouse signals), `Map` and `Player`. It handles the keyboard (`keyPressEvent`), creates the Bot in `start()` after a 3 s countdown, spawns a chest every 30 s, and makes the camera follow the player (`changeSceneRect`: centred on the player, clamped to the map, sized to the view's viewport).
- **`Map`:** 150×150 grid of `GridElement` (each cell is 10 px, map is 1500×1500 px). Buildings are 4×4 cells at hardcoded positions in `map.cpp`, chests 2×1 cells. The cell `taken` flags drive spawning and pathfinding.
- **Scene items:** `ItemsOnScene` (abstract `QGraphicsRectItem`: `attackItem()`, `height` used by grenade collision) → `Building`, `Chest`, `Hero` (abstract, also `QObject`) → `Player`, `Bot`.
- **Combat:** `Gun` → `Pistol` / `Rifle` / `Shotgun` / `Sniper` (stats set in the subclass constructors; `bulletSpeed` px per 10 ms step, 5, the sniper 10; a single-shot gun with a `fireFrequency` can't fire again before it has passed, `Gun::readyToFire`, so the sniper fires once per 1.5 s). `Shooting` runs fire timers and spawns `Bullet`s (the shotgun fires 5 spread bullets). `Grenade` handles its arc, bounces and explosion (`GrenadeEllipseItem` animation, `ShakeScreen`). It flies at 40 + power px/s (power 0–100, from holding Q) until its arc reaches the ground, and explodes 5 s after the throw: power 0 lands ~90 px away, 50 ~400 px; stronger throws are still in the air at 5 s. `Grenade::flightDistance` / `powerFor` convert between the two. It bounces off anything taller than its current height (`ItemsOnScene::height`: buildings 50, heroes 10, chests 5), the thrower included; it leaves the hand at 10, so the thrower never stops it. Hitting something from the side (`move()`: the grenade's whole 4×4 box one step ahead against each item's real shape, `touches`) reverses dx if the sideways part of the step runs into it, dy if the up/down part does, both at a corner, and it stays put that step; sinking below an item's top while already over it (coming down on a roof, a chest or a hero's head) bounces it back the way it came (`bounceBackIfComingDownOnSomething`).
- **Bot AI** (`bot.cpp`): each 20 ms tick it looks around with the player's view: a screen-sized area around it, of which `FieldOfView::canSee` keeps what is within 20° of its facing (`NOTICE_ANGLE`) or 30 px, with no building in between. It faces where it walks, or the target while attacking. It attacks when it has line of sight (no `Building`/`Chest` in between), hides while reloading, otherwise walks to a chest or a random point. When it loses sight of the player it walks to the last seen spot, turns a full circle there (`LOOK_AROUND_TICKS`) and only then gives up; chests are ignored meanwhile. When blocked it falls back to `BFS_Algorithm` pathfinding on the grid. Grenades (`Bot::throwGrenadeAt`): when it loses sight of the player it throws one at the last seen spot, and while reloading with the player in view it throws one at the player. Only for targets 100–390 px away, at most one live grenade and one every 6 s. It dodges its own live grenades and others' grenades it has seen (`noticeGrenade`, remembered where last seen until they go off; one it never saw it ignores): within 70 px it moves away unless already heading away, and it won't walk to, or past, a spot within 70 px of one (it waits until it has gone off).
- **Sniper scope** (`MapWidget::toggleScope` on right click, sniper only): the hero stands still (WASD ignored) and its screen can move away from it: `Hero::setScope(on, offset)`, `Hero::viewCentre()` = centre + offset, which `changeSceneRect` follows and the bot's view area uses too. Without Shift the mouse only moves the cursor; holding Shift (`setPanning`) the mouse moves the target, `lookPoint` (`cursorMoved` measures the movement and puts the cursor back with `QCursor::setPos`, which needs X11, not Wayland; the viewport grabs the mouse while Shift is held, so movement outside the window still arrives, and every way out of panning goes through `setPanning(false)`, which releases it). The target stays a pixel inside the map, so the cursor over it is always on the view. The target is always somewhere the hero can see: on the map, within `MAX_LOOK_DISTANCE` (1000 px), not behind a building (`FieldOfView::clearDistance`). Pressing Shift starts it under the cursor, or at the nearest such point towards it (and the cursor goes there). `panScope` refuses a step that would break that and tries the step's x and y parts alone, so it slides along a building. `followTarget` moves the screen so the target stays under the still cursor; where the screen can't follow (the map's edge, `cameraCentreFor`: its centre stays 501..999 across), the cursor moves to the target instead. The hero aims at `lookPoint`. `showScopeMode` shows the mode: a crosshair cursor and a line at the top while scoped, a move cursor and "moving the view" while Shift is held. Visibility is still from the hero (the cone reaches 2000 px). Another gun, right click again or death leaves the scope; pausing lets go of Shift. The bot doesn't use the sniper yet (TODO 17 in `main.cpp`).
- **Player's view:** `FieldOfView` raycasts against the buildings from the hero's centre. It gives a 30° fully visible cone along the aim, reaching to the screen edge, then a further 10° on each side (`PERIPHERAL_ANGLE`) that fades linearly to dark. The fade is 0.5° solid slices drawn without antialiasing; don't use `QConicalGradient`, which costs ~6 ms a frame. Add to that a 30 px circle around the hero. Rays that hit a wall continue `WALL_DEPTH` (3 px) into it, so only the wall faces in line of sight show up; the rest of the building stays dark. `MapView::drawForeground` paints black over everything and erases each `VisiblePiece` with `DestinationOut`, as strongly as its brush's alpha. `MapWidget::updateFieldOfView` refreshes it on `Hero::viewChanged` (emitted by `Player::updateLineHeroMouse`) and `posChanged`, at most once per 16 ms frame: the first change is drawn at once and the latest one when the frame ends, so a fast mouse can't force hundreds of redraws a second. `MapView` keeps the darkness for the whole screen in `fogCache` and rebuilds it only when the view or the camera changes. Small repaints (bullets, the bot, the hero turning) just copy from it. The overlay isn't a scene item, so it never affects collision or bot checks. Don't merge the pieces with `QPainterPath::united()`: it breaks on the edges that rays share with buildings.
- **Shot marker:** every gunshot calls `Hero::announceAttack()` with the shooter's centre (from `Shooting::shot`, once per shot, also for the shotgun's 5 bullets), and every grenade explosion with where it went off (`Grenade::explode`; throwing marks nothing). That reaches `MapWidget::heroAttacked`. If an enemy did it and the player is alive, `MapView::showShot` marks it, hit or miss; being hit alone marks nothing. Death clears it (`Hero::died`). `ShotMarker` is one red arc 14 px around the player, pointing at where the shot was fired from. Every shot replaces it: it blinks (`BLINK_MS`), holds for 0.5 s, then fades over 1.5 s. It is always solid red with a dark edge (transparency would turn it pink over the light ground). Distance only makes it thinner, linearly down to `MIN_STRENGTH` of `WIDTH`, and a shot from further than 75% of the way to the screen edge in that direction isn't marked (an earlier marker keeps fading). `MapView` draws it in `drawForeground` after the darkness and repaints only its small area every 16 ms while it shows.
- **Stats:** `HeroStats` (kills/deaths) → `LeaderboardSlot` → `Leaderboard` (shown while X is held).
- **Constants** (`RELOADING_TIME`, map/window sizes) and the `guns` enum live in `global_consts.h`.
- Death → `Hero::resetHero()`: respawn at a random free cell after `TIME_RETURN_TO_LIFE` (3 s).
- Teardown: `~MapWidget` stops its timers, deletes bullets, grenades and bots first (they run timers and point at heroes), then the player, the map (which frees its grid) and the view, and the scene last, which deletes the buildings and chests. `HeroStats` works without a leaderboard row (`slot` may be null).

## Conventions

- Connections use function pointers (`connect(a, &A::signal, b, &B::slot)`), never `SIGNAL()`/`SLOT()` strings, so the compiler checks them. A lambda always gets a context object (`connect(a, &A::signal, receiver, [..]{...})`), so it's disconnected when the receiver goes. A widget never connects to its parent's slots: it emits a signal and the parent connects it.
- **Game time:** anything that happens over time in a game uses the `GameClock`, so that pausing freezes it: `GameTimer` instead of `QTimer`, `GameClock::singleShot(ms, context, lambda)` instead of `QTimer::singleShot` (dropped if the context is deleted first), `GameClock::now()` instead of wall-clock time, and `GameClock::track(animation)` after starting a `QPropertyAnimation`. Only pure rendering timers (the field-of-view throttle, the shot marker's repaint) stay `QTimer`. Tests that pause the clock must `GameClock::reset()` afterwards.
- Many members are created with in-class `new` initializers and deleted manually in destructors.
- Hero state changes `emit` signals (`hpChanged`, `ammoChangedNoReloading`, …). Lambdas in the `MapWidget` constructor forward them to `PlayerBarWidget`.
- Movement is 2 px per 20 ms tick. Collision checks call `Hero::isBlockedAt()` on the two leading corners of the 10 px hero. It checks every item at the point. Don't use `scene->itemAt()` for collision: it only returns the topmost item, so explosions and bullets hide walls.
- Bullets hit via `collidingItems()` (their whole rotated 4×2 px shape), skipping their owner and anything that isn't `ItemsOnScene`.
- Bot chest routing: chest cells are taken, so the bot targets the nearest free cell beside the chest (`Bot::freeCellNextToChest`) and plans the route once. The loose 25 px arrival tolerance applies only to that final stop, never to waypoints.
- Coordinates flip between grid units and pixels with ×10 / ÷10, so watch which one a value is in.
- `GridElement`s are shared map state. Never change their coordinates. `BFS_Algorithm::getPath` returns pixel `QPoint` copies.
- Chests: `Chest::open()` only hands out loot. The caller must then call `Map::removeChest()`, which frees the grid cells and deletes the chest.

## Controls
